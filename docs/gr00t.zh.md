# GR00T 接入：稀疏标签与专家动作窗口

[English](gr00t.md)

## 生成训练输入包

安装 `requirements.txt` 后，使用完整审核 JSON：

```bash
python tools/prepare_training.py \
  --review /path/to/subtask-review.json \
  --dataset /path/to/lerobot-dataset \
  --output-dir reports/training-package \
  --horizon 30 --history 4
```

DAgger 参考整理脚本要求 Parquet 中存在 `intervention.valid` 和 `intervention.mode`，缺少时会报错，不会自动把全部动作当成专家动作。没有接管字段的普通示教数据，需要先明确另一套专家数据规则，再使用适配代码。

脚本检查所有保留片段已经人工确认，以及 FPS、ID、文本和帧边界的一致性。输出原审核文件及 SHA-256、归一后的 Episode 标注、完整全局映射、逐帧掩码和汇总数字。原始 Parquet 和 MP4 不变。这个输出是输入包，**不是一个完整的 LeRobot 数据集**。

关节空间到末端空间等状态／动作表示转换，继续由已有 GR00T 数据流程完成；转换后必须保持原始帧数和对齐关系。构建动作采样器时，跳过没有有效动作起点的 Episode。

## 训练端需要做什么

`tools/gr00t_adapter.py` 是独立参考代码。原流程使用基于 `d2b7e75b937e3ec9aa5dbc798f08b89692c49734` 的自定义 Isaac-GR00T 分支，已包含子任务 prompt 和定制采样器。这个仓库不会自动修改一个全新的上游安装。

接入位置：

1. **Episode 加载器**：标签初始化为 `-100`，只在精确的 `[start,end)` 内填入保留任务。不能把前一任务扩展到后一任务起点，填掉删除／未知空隙。通过完整映射选当前子任务 prompt，另行保留总任务描述。稀疏人工标签不使用旧的提前 15 帧切换 prompt 规则。
2. **动作采样器**：只从 `action_sample_start_mask` 为 true 的位置取样。起点 `t` 对应原始数据 `t:t+30`，不能靠填充、截断、末尾重复或循环跳转把无效窗口变有效，也不能跨删除空隙拼接时间。
3. **规划器数据集（可选）**：使用 `subtask_id` 与 `planner_sample_mask`。未接管但标签有效的图像可以训练分类器。4 帧历史不能包含删除、未知、排除帧；Episode 开头重复第一帧，不跨空隙补历史。
4. **归一化统计**：另行决定哪些源数据参与统计。这些掩码约束动作监督，不会自动重算 GR00T 的统计量。

推理时，已有规划器预测原全局 ID，再选择对应子任务 prompt。训练这个动作包不会更新规划器；需要更新时，应单独训练并验证。

## 掩码含义

| 数组 | 含义 |
|---|---|
| `subtask_id` | 有效保留帧的原全局 ID，其余为 `-100` |
| `retained_frame_mask` | 有明确任务标签、未删除、未排除的帧 |
| `expert_retained_frame_mask` | 保留帧且接管有效，mode 属于 `{2,3}` |
| `action_sample_start_mask` | 完整动作窗口都由专家执行，且属于同一保留子任务 |
| `planner_sample_mask` | 当前标签和所需图像历史有效 |

同类、首尾接触的片段可以合并；两端 ID 相同也不能跨删除／排除空隙合并。不同任务不能共享动作窗口。完整有效 30 帧只有一个采样起点，29 帧没有起点。

例如任务 3 `[100,150)`、删除 `[150,160)`、任务 3 `[160,220)`，两个任务 3 区间仍然分开。如果全部保留帧均为专家帧，窗口 30，则起点为 `[100,121)` 和 `[160,191)`，没有任何窗口跨删除区间。

动作策略训练取的是窗口，并不按顺序学完整条 Episode。新增部分 Episode 只要观测、动作、prompt 和采样窗口一致，就能用于补强某个子任务，无需补出缺失的前后任务。
